# marketplace-services-status

The local control panel for the platform's systemd **user** units: a Koa + `ws` server on port 2901
that runs one batched `systemctl show` per tick, TCP-probes each configured port, and streams the
snapshot to a browser page that can start, stop and restart units and tail their journal. Not a repo of
its own — a tracked directory of the parent workspace, gated by the parent's hooks (ADR-025), so a
change here commits under the parent's rules.

`services.json` is the only source of truth: 6 groups over the 9 backend services and the 3 frontend
dev servers. Adding a service is an entry there plus a re-run of `yarn systemd:install` — no code change
anywhere.

## ⚠️ NEVER run the mutation gate by hand

`yarn test:mutation` is **hook-only** — it runs when `pre-push` calls it, never on demand, never for one
file, never to confirm a survivor is fixed. Never invoke `stryker` directly either. A survivor is
answered by writing the test it names; to reproduce one, apply the mutant by hand and run `yarn test`
(seconds, and names the tests that should have failed). Full rationale in [`REPO.md`](./REPO.md).

## Hard rules and traps

- ⚠️ **A service `id` *is* its systemd unit name.** `${id}.service` is synthesised in `config.ts`; no
  `unit` field is ever read from `services.json`. Renaming an `id` silently retargets which real unit
  `start`/`stop`/`restart` acts on.
- ⚠️ **Deleting an entry from `services.json` does not retire its unit.** Removal happens only on the
  next `install.sh` run, through a manifest diff, and only when the on-disk file still carries
  `generate.mjs`'s `# GENERATED by …` banner. Until then the orphan is still installed and still
  reached by `PartOf=marketplace.target`, while the monitor page — which reads only the current
  `services.json` — cannot see it.
- ⚠️ **The install manifest lives outside the repo and outside git**
  (`~/.config/systemd/user/.marketplace-status-manifest`) and survives re-clones and branch switches —
  `git status` never mentions it, so a stale one can drive orphan removal on a fresh checkout.
- ⚠️ **The WebSocket upgrade path bypasses Koa** and re-implements the Host/Origin/token checks by hand
  in `server.ts`. The two copies can drift and nothing enforces that they don't. A new mutating route
  or WS message type must be wired into that same-origin check too — `test/security.live.test.ts` is
  what proves the WS path actually invokes it.
- ⚠️ **`BIND_ALL` gates `HOST`, not the other way round.** With `BIND_ALL` false (the default), bind is
  hardcoded `127.0.0.1` and `HOST` is never read. `BIND_ALL=true` throws at startup unless `AUTH_TOKEN`
  is non-empty.
- ⚠️ **`AUTH_TOKEN=''` means "no auth configured", not "an empty credential"** — normalised to `null`
  once, in `loadEnv()`. Any code that re-derives "is auth on?" without reusing that null-ness reintroduces
  a `timingSafeEqual` an empty token matches.
- ⚠️ **Security response headers are set only inside the `GET /` handler** — not on `/api/*`, not on
  static assets. A new route ships with no framing/sniffing protection unless it sets them too.
- ⚠️ **`yarn test:unit` skips both security suites** (`security.test.ts`, `security.live.test.ts`) — it
  exercises none of the Origin/Host/CSRF/DNS-rebinding guards. Only `yarn test`/`yarn test:cov` build
  `dist/` first; a bare `vitest run` can pass while testing stale code.

Line-level invariants that mutation testing protects (health-derivation order, `refresh()` vs `tick()`,
`showUnits` matching, and more) aren't hard rules to memorise, but read [`REPO.md`](./REPO.md) before
touching `src/monitor.ts`, `src/systemd.ts`, `systemd/generate.mjs` or `src/public/app.js` — refactoring
one of those lines "for clarity" is how the mutation gate goes red.

## Gates

- **100% statements, branches, functions and lines; mutation `break: 100`. Never lower either** — a
  change that needs a threshold lowered needs a test instead, never a smaller number.
- **The parent workspace's hooks gate this directory**, not a hook of its own — `pre-commit` runs
  `yarn typecheck` + `yarn test:cov` + Qodana on staged paths here, `pre-push` runs the full unscoped
  chain including mutation. Why the split, and what `coverage-audit.mjs` proves beyond vitest: [`REPO.md`](./REPO.md).
- **Semgrep is a push-only gate.** Bypass for a Docker outage, never for a finding:
  `SKIP_SEMGREP=1 git push`.
- Commits here land in the parent repo. **Never commit on `main`** — branch first with
  `git switch -c <type>/<slug>`; merging into `main` is the user's decision alone.
