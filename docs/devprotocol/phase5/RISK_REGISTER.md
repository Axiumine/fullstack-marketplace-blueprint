## 1. Purpose

Every real risk Marketplace carries. Brownfield retrofit - most rows already fired at least once on
this platform, not hypothetical. [`docs/testing.md`](../../testing.md), [`docs/workflow.md`](../../workflow.md) and [`docs/conventions.md`](../../conventions.md) are the densest sources; every
row below traces to it plus `phase3/SECURITY_AUTH.md`, `phase2/EVENT_STORMING.md` §5-6,
`phase2/BOUNDED_CONTEXT.md` §7, `phase1/PDR.md` §6/§8, `phase3/INFRA.md` §13-14, `phase4/API_CONTRACTS.md`
§9, `phase4/ERROR_HANDLING.md` §Layer 8. Score honest per `phase5/CONSTRAINTS.md` instruction: a risk
already mitigated by shipped code gets a **low residual**, not a low likelihood - the underlying
condition (no cross-repo test, structural mutation-testing trap, local-only git hook config) stays
exactly as likely to recur elsewhere as before the one instance was fixed.

## 2. Risk scoring

**Likelihood:** 1 (rare) → 5 (almost certain)
**Impact:** 1 (negligible) → 5 (project-threatening)
**Score:** Likelihood × Impact

| Score | Level |
|---|---|
| 1-4 | 🟢 Low |
| 5-9 | 🟡 Medium |
| 10-16 | 🟠 High |
| 17-25 | 🔴 Critical |

## 5. Risks accepted (not actively mitigated)

Known, explicit, no further work planned unless the trigger fires:

- **R13 - Pre-commit history is permanently gone.** History in all 16 repos starts at the 2026-08-04/05
  rename. The 2026-08-04 catalogue+collection deletion happened before any of these commits existed, on
  the user's explicit instruction after the risk was stated. No git operation in this tree can recover it.
- **R16 - `npm publish` is a one-way door.** Irreducible property of the npm registry, not a platform bug.
  Accepted as the cost of `marketplace-common`'s standing publish permission; mitigated only by bump
  discipline, never by a technical control.
- **R40 - Three authorization services stay three processes.** Merging into one was evaluated and
  explicitly rejected (ADR-006, `docs/decisions/authorization-service-consolidation.md`): one
  `process.exit(1)` taking down all three tiers' token lifecycle was ranked worse than the deduplication a
  merge would buy. The per-tier crash-domain isolation this buys is itself the accepted risk boundary - a
  crash in one tier's own authorization service still fully blocks that tier alone.
- **R41 - Fixed-window rate limiting allows a 2× burst at the window boundary.** Deliberate tradeoff:
  "make automation expensive, not meter a paid API." A sliding-window limiter was not chosen. Revisit only
  if a real brute-force incident is observed.
- **Qodana `SKIP_QODANA=1` escape hatch.** Exists platform-wide for any repo missing a `QODANA_TOKEN` or a
  Cloud project. Accepted as a documented bypass, not a silent one - both `.githooks/pre-commit` and
  `pre-push` still gate coverage and mutation score even when this fires.
