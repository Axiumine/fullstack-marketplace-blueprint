## 1. Epic goal

Record the gap, not close it. This epic names Cart, Order, Delivery, Payment for glossary and boundary
readiness (`phase2/BOUNDED_CONTEXT.md:190`) and lists what blocks starting design. It ships no
collection, no migration, no model, no resolver, no schema builder, no state machine, no sequence
diagram of a checkout flow. Per `phase5/CONSTRAINTS.md` §6: "a risk-register row naming the gap is fine;
a story designing the fix is not."

## 2. Scope

| In scope | Out of scope | Why |
|---|---|---|
| Naming the gap and its blocking questions | A cart schema or mutation | No design exists; inventing one violates [`CLAUDE.md`](../../../../CLAUDE.md) §Build state "ask before inventing them" |
| Citing what `item` already lacks because of this gap | An order state machine or resolver signature | `phase5/CONSTRAINTS.md` §6 — "no story defines a state machine, no story defines a resolver signature" |
| Recording the open questions that block design start | A delivery-cost model | No design exists; naming one is designing one |
| — | A payment gateway or error taxonomy | No gateway chosen, no integration story permitted |

## 3. Build state

**Not built.** Verified empirically this pass, not assumed:

- `find BEs/dev -path "*/mutations/*" -iregex '.*\(cart\|order\|payment\|delivery\).*'` — zero matches
  across all 9 backend services under `BEs/dev/`.
- No collection named `cart`, `order`, `delivery`, or `payment` in `BEs/marketplace-db-setup/lib/schemas/`
  — that directory holds exactly `account.js`, `collection.js`, `geo.js`, `shopOwner.js`, `company.js`,
  `user.js`, `item.js`, `itemCategory.js`.
- `item` deliberately carries no `price` field — `BEs/marketplace-db-setup/lib/schemas/item.js`:
  "There is no `price`. Cart, order, delivery and payment have no model anywhere on this platform and no
  design decision behind them yet, so a price would be a guess at a currency, a precision, a VAT
  treatment and a discount model all at once."
- Delivery has no collection, no resolver, and no design anywhere on this platform — ADR-008. No
  successor exists.
- `phase2/UBIQUITOUS_LANGUAGE.md` §18 "Planned commerce vocabulary — NOT BUILT" lists Cart, Order,
  Delivery, Payment each as `NOT BUILT`, named for glossary readiness only.
- `phase4/API_CONTRACTS.md:516-518`: "Operations that do not exist and are not designed: anything
  ordering-related — cart, order, delivery, payment. No collection, no resolver, no schema slice, no
  ADR."
