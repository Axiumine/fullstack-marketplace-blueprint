## 1. Epic goal

Make the auth boundary's *refusals* as well tested as its acceptances, and make the documents stop describing a
platform that does not exist. Coverage here is 100% on four metrics with mutation score 100, and the tier
rejection path is still untested in two of three resource services — because a fully covered happy path can sit
next to an unexercised guard and the numbers stay green. This epic closes that, closes the audit's remaining
blind spots, and leaves behind a checklist so the next audit costs less than this one did.

## 4. Stories

### E18-S01 — Every resource service proves it rejects the wrong tier   `built 2026-08-13`
**As a** platform, **when** a valid session for one tier is presented to another tier's resource service,
**I want** a test in *that service* proving the 403 **so that** a refactor of its middleware cannot silently
open it.
**domains:** backend, testing
**Acceptance criteria:**
- `marketplace-dev-authenticated-resource` and `marketplace-dev-admin-authenticated-resource` each gain a
  reject-path test modelled on
  `marketplace-dev-user-authenticated-resource/test/authorizationAuthenticatedResourceHandler.test.mts:52-89`,
  asserting the 403 and the response body shape, not merely a non-200
- Each service also tests the **missing-tier** case — a session hash with no `tier` field — asserting it is
  refused rather than treated as a wildcard, which is ADR-004's whole point
- The tests drive the service's own handler, not `assertTier` directly; a test that calls the shared helper
  does not prove the service reaches it
- `yarn test:cov` stays 100/4 and `yarn test:mutation` stays 100 in both services with no threshold changed and
  no exclusion added
**Traces:** NFR-SE01, NFR-SE02, NFR-SE05, NFR-MA01, NFR-MA02; ADR-002, ADR-004; BCON-01, BCON-02
**Evidence (gap):** no equivalent test file in either service's `test/` directory

**Evidence (built): satisfied, and this epic did not build it.** The story was written on 2026-08-10 against
a workspace where one service tested the reject path. Verified 2026-08-13: all three resource services now
carry `test/authorizationAuthenticatedResourceHandler.test.mts`, and every criterion above is met by tests
that landed with the tier discriminator itself (`2f8257b` in `marketplace-dev-authenticated-resource`,
"refuse a foreign-tier access token, and prove it") rather than under this epic.

| Service | Wrong tier | No tier | 403 not 401 |
|---|---|---|---|
| `-authenticated-resource` | `it.each([['admin'], ['user']])` | `refuses a session with no tier at all` | `extensions.http.status` asserted `403` |
| `-admin-authenticated-resource` | `it.each([['shopOwner'], ['user']])` | same | same |
| `-user-authenticated-resource` | `it.each([['shopOwner'], ['admin']])` | same | same |

All three drive `authorizationAuthenticatedResourceHandler()(ctx, next)` — the service's own middleware, not
`assertTier` — and assert `ctx.state.user` stayed `undefined` and `next` was never called, so a handler that
threw *after* populating state would fail them. The missing-tier case is refused by `actual !== expected`
with no branch of its own, which is what makes a tier-less session fail closed rather than act as a wildcard
(ADR-004). Each suite additionally pins that the introspection bypass cannot rescue a foreign-tier token —
`does not let the introspection code rescue a bearer token from another tier` — which is the hole the two
mechanisms would otherwise leave between them.

**Gates:** unchanged, because no source or test changed to close this. `marketplace-dev-authenticated-resource`
— 182 tests, coverage 100% on all four metrics (180/180, 49/49, 48/48, 176/176).
`marketplace-dev-admin-authenticated-resource` — 647 tests, 100/4 (597/597, 213/213, 137/137, 550/550).
`marketplace-dev-user-authenticated-resource` — the reference implementation, unchanged since E15-S05.

### E18-S02 — The auth boundary is tested the same way in every service   `built 2026-08-13`
State plainly: the reason one service had the test and two did not is that there is no shared expectation of
what an auth-boundary test suite must contain.
**domains:** backend, testing, documentation
**Acceptance criteria:**
- A written contract lists the cases every authenticated service's boundary suite must cover: valid session
  accepted, wrong tier refused, missing tier refused, absent token refused, malformed token refused, expired
  session refused, and — once E14 lands — replayed token refused
- Every one of the seven authenticated services has a test file covering all cases in the contract; a
  meta-test or a documented checklist enumerates the services and fails when one is missing a case
- The contract lives in `docs/testing.md` next to the existing vitest layout, not in an epic file
- The `INTROSPECTION_CODE` path gets the same treatment: accepted with the right code, refused with a wrong
  one, refused with none
**Traces:** NFR-SE01, NFR-SE02, NFR-SE05, NFR-MA01, NFR-MA02, NFR-MA05; ADR-004; BCON-01, BCON-02, BCON-03
**Evidence (gap):** three resource services, three different boundary-test shapes

**Evidence (built).** Eleven cases, `AB-01`..`AB-11`, live in
`BEs/marketplace-common/src/others/authBoundaryContract.mts` — the list, a per-service exemption map with a
written reason for every excusal, and `requiredAuthBoundaryCases(service)`. Each of the seven authenticated
services carries a `// AB-xx:` comment above the test that proves the case and a
`test/authBoundaryContract.test.mts` that reads its own boundary suite and fails on a missing tag. The whole
contract is written up in [`docs/testing.md`](../../../testing.md), *The auth-boundary contract* — the table,
the seven-service enumeration and the exemptions.

**Open question 1 is answered: a meta-test, but a per-repo one.** Each service scans only its own `test/`
directory, so no service reads another's files and BCON-05 is not strained; the only shared thing is the
case list, which travels the way every other shared thing does, as a `marketplace-common` export. A service
the contract has never heard of cannot ask what it owes — `requiredAuthBoundaryCases` throws rather than
answering an empty list, which is what makes a new service's suite fail until somebody writes its row.

| Service | Cases | Notes |
|---|---|---|
| `-authenticated-resource` | 10 | AB-07 excused — mints no token |
| `-admin-authenticated-resource` | 10 | same |
| `-user-authenticated-resource` | 10 | same |
| `-authenticated-authorization` | 11 | gained AB-07 and AB-11 |
| `-admin-authenticated-authorization` | 11 | same |
| `-user-authenticated-authorization` | 11 | same |
| `-authenticated-logout` | 8 | AB-02/AB-03 excused — serves all three tiers (ADR-005) and asserts none; AB-07 excused |

⚠️ **The contract found two real holes, both in the three authorization services**, which is the answer to
whether an exercise like this is bookkeeping. **AB-11** — the `INTROSPECTION_CODE` environment allowlist of
E13-S11 — was tested in the four other services and in none of these three. **AB-07** — the replay refusal of
E14-S02 — was asserted only from the writing side: `refresh.test.mts` proved the tombstone was *written* and
nothing proved a replayed token was *refused* or its family revoked. Both are now covered: the new test
drives the handler with a token whose session is gone and whose tombstone is older than the ten-second grace
window, and asserts the lineage read, one `del` per member with the family set deleted last, and the ordinary
498 the caller gets — a replayer learns nothing from the response about whether the revocation happened.

⚠️ **A tag is a claim the scanner cannot check.** It catches the case nobody wrote a test for, not a tagged
test gutted while its tag stayed; that one is caught by mutation testing, one gate later. The scanner was
verified non-vacuous by renaming a tag and watching the suite fail, and each file asserts it read a non-empty
suite and a non-empty case list.

added. `marketplace-common` — mutation 100.00, 55 mutants on the new module, all killed.
