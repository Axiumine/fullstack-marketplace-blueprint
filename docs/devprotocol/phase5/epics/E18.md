## 1. Epic goal

Make the auth boundary's *refusals* as well tested as its acceptances, and make the documents stop describing a
platform that does not exist. Coverage here is 100% on four metrics with mutation score 100, and the tier
rejection path is still untested in two of three resource services — because a fully covered happy path can sit
next to an unexercised guard and the numbers stay green. This epic closes that, closes the audit's remaining
blind spots, and leaves behind a checklist so the next audit costs less than this one did.

## 3. Build state

**Partly built — one service does it right.**

- `BEs/dev/marketplace-dev-user-authenticated-resource/test/authorizationAuthenticatedResourceHandler.test.mts:52-89`
  is the reference implementation: it drives a session whose `tier` does not match the service and asserts the
  403. Neither `marketplace-dev-authenticated-resource` nor `marketplace-dev-admin-authenticated-resource` has
  an equivalent.
- `assertTier` itself is tested — `BEs/marketplace-common/src/others/assertTier.mts:13-16` — so the shared
  helper is fine. What is untested is that each service actually *reaches* it with the right expectation, which
  is the part that a refactor would break silently.
- Coverage and mutation gates are at 100 across 15 packages, which is exactly why this gap is worth naming: the
  numbers do not distinguish "this branch is impossible" from "this branch is never driven".
- `BEs/dev/marketplace-dev-public-authorization/src/index.mts:26-46` declares 16 `REQUIRED_ENV_VARS`, asserted
  by nothing.
- The audit was static-only, single-pass, and never ran the platform (audit §5).

## 4. Stories

### E18-S01 — Every resource service proves it rejects the wrong tier   `not built`
**As a** platform, **when** a valid session for one tier is presented to another tier's resource service,
**I want** a test in *that service* proving the 403 **so that** a refactor of its middleware cannot silently
open it.
**domains:** backend, testing
**Acceptance criteria:**
- `marketplace-dev-authenticated-resource` and `marketplace-dev-admin-authenticated-resource` each gain a
  reject-path test modelled on
  `marketplace-dev-user-authenticated-resource/test/authorizationAuthenticatedResourceHandler.test.mts:52-89`,
  asserting the 403 and the response body shape, not merely a non-200
- Each service also tests the **missing-tier** case — a session hash with no `tier` field — asserting it is
  refused rather than treated as a wildcard, which is ADR-004's whole point
- The tests drive the service's own handler, not `assertTier` directly; a test that calls the shared helper
  does not prove the service reaches it
- `yarn test:cov` stays 100/4 and `yarn test:mutation` stays 100 in both services with no threshold changed and
  no exclusion added
**Traces:** NFR-SE01, NFR-SE02, NFR-SE05, NFR-MA01, NFR-MA02; ADR-002, ADR-004; BCON-01, BCON-02
**Evidence (gap):** no equivalent test file in either service's `test/` directory

### E18-S02 — The auth boundary is tested the same way in every service   `not built`
State plainly: the reason one service had the test and two did not is that there is no shared expectation of
what an auth-boundary test suite must contain.
**domains:** backend, testing, documentation
**Acceptance criteria:**
- A written contract lists the cases every authenticated service's boundary suite must cover: valid session
  accepted, wrong tier refused, missing tier refused, absent token refused, malformed token refused, expired
  session refused, and — once E14 lands — replayed token refused
- Every one of the seven authenticated services has a test file covering all cases in the contract; a
  meta-test or a documented checklist enumerates the services and fails when one is missing a case
- The contract lives in `docs/testing.md` next to the existing vitest layout, not in an epic file
- The `INTROSPECTION_CODE` path gets the same treatment: accepted with the right code, refused with a wrong
  one, refused with none
**Traces:** NFR-SE01, NFR-SE02, NFR-SE05, NFR-MA01, NFR-MA02, NFR-MA05; ADR-004; BCON-01, BCON-02, BCON-03
**Evidence (gap):** three resource services, three different boundary-test shapes

### E18-S03 — The env-var contract is asserted, not assumed   `not built`
State plainly: E16-S06 removes an env var from five services. Nothing currently fails if a required var is
dropped from the list, or added to the list and never read.
**domains:** backend, testing
**Acceptance criteria:**
- Each of the nine services has a test asserting its `REQUIRED_ENV_VARS` array with `toStrictEqual` against an
  exact expected list — not a length check, which passes on a swap
- A test proves the service fails to start when a required var is absent, for at least one var per service
- No test, fixture or snapshot in this story reads or prints a value from `.env`; only the committed `env`
  templates and the variable **names** appear anywhere
- `marketplace-dev-public-authorization`'s expected list has 16 entries today and whatever E16-S06 leaves it
  with afterwards
**Traces:** NFR-AV01, NFR-SE12, NFR-MA01, NFR-MA02, NFR-MA05, NFR-CO01; BCON-01, BCON-02
**Evidence (gap):** `BEs/dev/marketplace-dev-public-authorization/src/index.mts:26-46`

### E18-S04 — Investigation: what is actually in the dependency tree   `not built`
State plainly: the audit examined this workspace's code and the handful of `node_modules` files it needed to
resolve a question. Nobody has looked at the tree as a whole.
**domains:** backend, documentation
**Acceptance criteria:**
- A written finding records the output of an advisory scan across all sixteen repos and states, per advisory,
  whether it is reachable from this platform's code paths — a list of CVE numbers with no reachability analysis
  is not a finding
- The finding names every dependency that participates in the auth path — `@axiumine/koa-utils`, `keygrip`,
  `cookies`, the Redis client, the Sentry packages — and its version, since three separate stories in this
  backlog are constrained by what those packages do
- The finding states which dependencies are external-and-unmodifiable from this workspace, so future epics stop
  rediscovering that boundary
- Anything actionable becomes a story; anything accepted becomes a `RISK_REGISTER` row
**Traces:** NFR-SE06, NFR-SE08, NFR-MA05, NFR-MA07, NFR-CO01; BCON-01, BCON-04
**Evidence (gap):** audit §5 — "No full dependency-tree audit was performed."

### E18-S05 — Investigation: what encryption at rest actually covers   `not built`
State plainly: ADR-029's CSFLE encrypts specific fields with per-collection DEKs. It is not a statement about
the storage layer, and the two are routinely confused.
**domains:** database, documentation
**Acceptance criteria:**
- A written finding lists every field currently encrypted through `encryptedFields.mts`'s `KEY_ALT_NAMES`, and
  every field carrying personal data that is **not**, with a reason per omission
- The finding states plainly whether the underlying MongoDB and Redis volumes are encrypted at rest in Dev and
  whether that is known for any other environment — and says "unknown" where it is unknown
- The finding covers Redis, whose session values are not personal data but whose keyspace is credentials until
  E13-S01 lands
- The result either closes the audit §5 item or becomes a story with an owner
**Traces:** NFR-SE06, NFR-SE07, NFR-MA05, NFR-CO01, NFR-CO02; ADR-029; BCON-01, BCON-04
**Evidence (gap):** audit §5 — encryption at rest named as adjacent and unexamined

### E18-S06 — The documents stop describing a platform that does not exist   `not built`
State plainly: six of the audit's findings were documentation defects. E15, E12 and E13 each carry the ones
adjacent to their own code. This story carries the rest.
**domains:** documentation
**Acceptance criteria:**
- Every documentation claim the audit contradicted is either corrected or shown to be already handled by
  E15-S08, E12-S14, E13-S04, E13-S06, E13-S07 or E13-S08 — a table in this story maps each audit finding to the
  file and line that closes it, with no finding unassigned
- `docs/architecture.md`'s auth-model section describes the session shape after this backlog lands: the tier
  discriminator, the family, the absolute cap, the index, the hashed keys
- The audit report itself gains a closing section recording which findings were fixed, which were accepted, and
  which were routed to the topology ADR — so v1.1 is not left reading as though nothing happened
- `grep`-checkable: no document still asserts `waitApprov` enforcement, a path-scoped refresh cookie, or an
  unrotatable signing key
**Traces:** NFR-MA05, NFR-CO01; BCON-01, BCON-03
**Evidence (gap):** audit §3.6e, §3.7b, §3.7c, §3.7d, §4

### E18-S07 — Risk register hygiene   `not built`
**domains:** documentation
**Acceptance criteria:**

  E16-S08 at minimum

### E18-S08 — The next audit is cheaper than this one   `not built`
State plainly: this audit was manual, static-only and single-pass. Most of it can be a script.
**domains:** testing, documentation
**Acceptance criteria:**
- A checklist in `docs/testing.md` enumerates the mechanical checks this backlog introduced — no raw token as a
  Redis key, no `rejectUnauthorized`, no unguarded `sendDefaultPii`, no network-derived value in a bucket key or
  a log line, no undocumented Redis key shape, boundary suite complete per E18-S02
- Each check names the command that runs it, and each command is one a developer can run locally
- Whatever can be a lint rule or a test is one, and the checklist says which items are still manual and why
**Traces:** NFR-MA01, NFR-MA05, NFR-MA07, NFR-CO01; BCON-01, BCON-02, BCON-03
**Evidence (gap):** audit §5 — static-only, single-pass

### E18-S09 — Investigation: run the auth path against the live stack   `not built`
State plainly: every finding in the audit, and every story in these seven epics, was derived by reading. None
was observed.
**domains:** backend, testing, documentation
**Acceptance criteria:**
- A written finding records the observed behaviour of login, refresh, logout and a tier-mismatched call against
  the running Dev stack, per tier — what is in Redis after each, what cookies are set, what the response says
- The finding explicitly confirms or corrects E15-S01's claim that logout is a silent no-op today, since that is
  the one live production defect in this backlog and it deserves an observation rather than an inference
- Any divergence between observation and these epics' §3 "Build state" sections is corrected in those sections
  in the same change
**Traces:** NFR-MA07, NFR-CO01; BCON-01, BCON-04
**Evidence (gap):** audit §5 — "static-only"
