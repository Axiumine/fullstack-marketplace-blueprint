## 1. Epic goal

Give the operator a window onto sessions and signing keys, and two blunt levers — revoke this session, revoke
this account's sessions — without ever putting a credential on a screen. This epic renders what E15 and E16
already enforce; it adds no security control of its own, because a control that fires when a human notices
something is not a control.

## 2. Scope

| Item | In/Out | Why |
|---|---|---|
| Read-only session list per account | In | closes the operator half of audit §3.6b |
| Revoke one session / revoke all of an account's sessions | In | the levers; both call E15's routine |
| A reuse-event trail — what was revoked, when, why | In | reuse detection (E14) that nobody can see is hard to act on |
| Key-custody screens over E16's resolvers | In | E16 ships resolvers; this ships the screen |
| Displaying a token, a token prefix, a key or a key prefix | **Explicitly out, permanently** | stated by the user as a condition of this epic existing |
| Any detection that depends on an operator looking | **Explicitly out** | detection lives in the hot path — E14, E15, E16 |
| A tenth deployable service for admin session tooling | Out | see E17-S09 |
| Anything network- or device-derived on a session row | Out | the standing GDPR decision — no IP, not truncated, not hashed, not salted |

## 3. Build state

**Not built**, and it cannot be built before its dependencies exist: there is no session index to list
(E15-S02), no reuse event to show (E14-S03), and no keyring to render (E16). What exists is the shell:

- `marketplace-admin` — React 19.2.8, Vite 8.2.0 (Rolldown), TypeScript 6.0.3, urql 5 / `@urql/core` 6,
  `@tanstack/react-router` 1.170, with hand-written `schema/*.graphql` slices that codegen types from.
- `marketplace-dev-admin-authenticated-resource` on 4025 is where Admin-tier domain resolvers already live.
- `marketplace-dev-admin-authenticated-authorization` on 4024 handles Admin token lifecycle only — no domain
  query belongs there.

## 4. Stories

### E17-S01 — The Admin schema slice describes sessions and keys before any type is generated   `not built`
State plainly: this repo's types are generated **from** hand-written schema slices. Running codegen before
editing the slice produces nothing and reads as a broken toolchain.
**domains:** frontend, backend
**Acceptance criteria:**
- `marketplace-admin/schema/admin-authenticated-resource.graphql` is edited by hand to add the session and
  key-custody types, queries and mutations, and **then** `yarn codegen` is run — the generated file is a build
  output of that edit, and the commit contains both
- A `GraphQLReuseEventAction` enum lives in its own file on the backend side and is referenced by both the
  schema slice and the resolver, so the frontend's generated union and the backend's runtime values cannot
  drift; a test asserts the two value sets are equal
- The session type carries no field named for, or capable of holding, a token; a test enumerates its fields
  against an exact expected set (BCON-01)
- `yarn lint` and `yarn typecheck` pass in `marketplace-admin` with no generated file edited by hand
**Traces:** NFR-MA01, NFR-MA05, NFR-CO01; BCON-01, BCON-03
**Evidence (gap):** `marketplace-admin/schema/admin-authenticated-resource.graphql` has no session types

### E17-S02 — An operator can list the sessions an account holds   `not built`
**As a** platform operator investigating a report of a compromised account, **when** I open that account,
**I want** its live sessions listed **so that** I can see how many there are and end them.
**domains:** backend, frontend, testing
**Acceptance criteria:**
- A `sessions(tier, accountId)` query in `marketplace-dev-admin-authenticated-resource` reads E15's
  `${REDIS_KEY}idx:<tier>:<accountId>` hash with `hGetAll` and returns one row per field, carrying the session
  id, its tier, its mint time and its family id — and nothing derived from a network address
- A test drives the resolver against a seeded index and asserts the serialised response, as a string, contains
  neither the seeded refresh token nor the seeded access token — a substring check, not a shape check
- The resolver runs Admin-tier only through `assertTier`, and **its reject path has its own test**, not just
  its accept path
- Stale index fields — sessions whose keys have already expired — are not rendered as live; the resolver either
  filters them or E15-S03's prune has already removed them, and a test covers whichever it is
**Traces:** NFR-SE01, NFR-SE02, NFR-SE05, NFR-MA01, NFR-MA02, NFR-CO01, NFR-CO02; ADR-002, ADR-004; BCON-01, BCON-08
**Evidence (gap):** no session query exists in the Admin resource service

### E17-S03 — An operator can end one session   `not built`
**As a** platform operator, **when** I revoke a single session, **I want** its two tokens gone and its index
row gone **so that** the list I am looking at stays true.
**domains:** backend, testing
**Acceptance criteria:**
- `revokeSession` deletes the session's keys with one single-key `del` each (BCON-08) **and** removes the
  session's field from the account index with `hDel` in the same routine — an index row surviving its session
  is the defect this criterion exists to prevent
- Revoking an already-dead session succeeds without throwing and still prunes the index field; tested
- The mutation is rate-limited through `assertUnderRateLimit` with no network-derived bucket key
- An integration test seeds a real session, revokes it through the resolver, and asserts the next authenticated
  call on that session's tier is refused; every seeded key registered at creation and drained in `afterAll`
  (BCON-09)
**Traces:** NFR-SE01, NFR-SE03, NFR-SE05, NFR-MA01, NFR-MA02; ADR-003; BCON-01, BCON-08, BCON-09
**Evidence (gap):** no revoke resolver exists

### E17-S04 — "Log out everywhere" is safe against a login that arrives mid-revoke   `not built`
State plainly: revoking every session reads the index, deletes what it found, then wants to delete the index
key — and a login landing between the read and that delete would have its index row destroyed while its
session stayed live, leaving an invisible session. That is the concurrency defect this story exists to close.
**domains:** backend, testing
**Acceptance criteria:**
- After the revoke loop, the routine **re-reads** the index. The index key is deleted only if its field set is
  unchanged; otherwise the routine `hDel`s exactly the fields it revoked, and repeats over the new ones
- The retry is bounded by a named constant and, on exhaustion, leaves the index key in place rather than
  deleting it — an orphaned field is recoverable, a destroyed index is not; tested at the bound
- A test simulates the race directly: the mock adds a field between the first `hKeys` and the delete, and the
  test asserts the index key was **not** deleted and the newcomer's field survived
- The same routine backs E15-S05's password-change teardown — one implementation, two callers, asserted by
  both call sites' tests referencing it
**Traces:** NFR-SE01, NFR-SE03, NFR-SE05, NFR-MA01, NFR-MA02, NFR-MA05; BCON-01, BCON-02, BCON-08
**Evidence (gap):** E15-S04's routine as first designed had no re-read; this story is the correction

### E17-S05 — Reuse events are recorded and readable   `not built`
**As a** platform operator, **when** a refresh token is replayed and a family is revoked, **I want** to see
that it happened **so that** a silent mass logout is explainable rather than a mystery ticket.
**domains:** backend, frontend, testing
**Acceptance criteria:**
- E14-S03's family revocation appends an event carrying the family id, the account, the action from
  `GraphQLReuseEventAction` and a timestamp — and **no token, no token hash preimage, and no network data**
- The event store has a stated retention and a stated bound on growth; a test proves the bound
- A query exposes the events to Admin tier only, with its `assertTier` reject path tested
- A test asserts the serialised event response contains no substring of the token that triggered it
**Traces:** NFR-SE01, NFR-SE02, NFR-SE05, NFR-MA01, NFR-MA02, NFR-CO01, NFR-CO02; ADR-002, ADR-004; BCON-01
**Evidence (gap):** E14-S03 revokes silently as designed

### E17-S06 — The console screens exist in `marketplace-admin`   `not built`
**As a** platform operator, **when** I need any of the above, **I want** it on a screen **so that** it is
usable without a GraphQL client.
**domains:** frontend, testing
**Acceptance criteria:**
- A `@tanstack/react-router` route renders the session table, the two revoke actions with confirmation, the
  reuse-event trail and the key-custody panel from E16-S07
- Both revoke actions and every key-custody mutation are behind an explicit confirmation step; a component
  test asserts the mutation does not fire without it
- Every destructive action states its blast radius in the confirmation text — how many sessions, whose
- `marketplace-admin`'s existing coverage thresholds are met with the new routes included; none lowered
**Traces:** NFR-US01, NFR-US02, NFR-MA01, NFR-MA02, NFR-CO01; BCON-01, BCON-02
**Evidence (gap):** no such route in `marketplace-admin/src/routes/`

### E17-S07 — The console cannot leak a credential, and a test proves it every run   `not built`
State plainly: "we agreed not to display tokens" is a convention. This story makes it a gate.
**domains:** backend, frontend, testing
**Acceptance criteria:**
- One test in the backend and one in the frontend seed a known token value and a known key value, exercise
  **every** query and mutation this epic adds, and assert the serialised response of each contains neither —
  a loop over the resolver list, so a resolver added later without the check fails the suite
- No component in the new routes renders a value read from a field capable of holding key or token material;
  enforced by the field-set assertions in E17-S01 and E16-S07
- No new log statement in this epic's diff interpolates a session or key value; asserted by a grep-shaped
  check over the diff
**Traces:** NFR-SE01, NFR-SE02, NFR-SE04, NFR-SE05, NFR-SE12, NFR-MA01, NFR-MA02, NFR-CO01; BCON-01, BCON-02
**Evidence (gap):** nothing prevents it today because nothing exists today

### E17-S08 — Key custody is operable from the console   `not built`
**As a** platform operator, **when** I need to rotate or retire a signing key, **I want** to do it from the
console **so that** rotation is a routine act rather than a deploy.
**domains:** frontend, testing
**Acceptance criteria:**
- The panel lists keys by id, state and timestamps only, renders rotate and force-retire behind confirmation,
  and surfaces E16-S04's "no key matched" error as a visible failure rather than a silent success
- Retiring the `current` key is not offered in the UI at all, matching E16-S04's server-side refusal — tested
- The stated propagation window from E16-S02 is shown next to the actions, so an operator is not misled into
  thinking a retire is instantaneous
**Traces:** NFR-SE04, NFR-US01, NFR-US02, NFR-MA01, NFR-CO01; BCON-01
**Evidence (gap):** E16-S07's resolvers have no consumer

### E17-S09 — The decision not to add a tenth service is written down   `not built`
State plainly: this epic adds Admin-tier session and key tooling to an **existing** service. That choice needs
a recorded reason, and the reason is operational cost, not an architectural prohibition.
**domains:** documentation
**Acceptance criteria:**
- A short decision note records that BC-12's resolvers live in `marketplace-dev-admin-authenticated-resource`
  rather than in a tenth deployable, and cites `RISK_REGISTER` R02, R03 and R04 — the operational-cost rows
  that actually justify it. It must **not** cite ADR-006 or NFR-AV01, neither of which forbids a tenth service
- `docs/architecture.md`'s service table is updated to say that the Admin resource service now also carries
  session administration and key custody
- The note states the condition under which the decision would be revisited
**Traces:** NFR-MA05, NFR-CO01; BCON-01, BCON-03
**Evidence (gap):** `docs/architecture.md` service table lists nine services and their concerns

## 5. Dependencies

- **Depends on E15-S02 and E15-S04** — the index and the revoke routine. E17-S04's re-read requirement is a
  correction *to* E15-S04 and must land with it, not after it.
- **Depends on E14-S01 and E14-S03** — `familyId` on the session, and the revocation whose events E17-S05 shows.
- **Depends on E16-S07** — the key-custody resolvers E17-S08 renders.
- **Blocks nothing.** It is the last epic that builds anything; only E18's coverage and documentation truth-up
  follows it, by construction.
- **Landing order** (BCON-05, BCON-07):
  1. `marketplace-dev-admin-authenticated-resource` — resolvers, the `GraphQLReuseEventAction` file, tests.
  2. `marketplace-common` — E17-S04's re-read, if E15-S04 has already landed without it.
  3. `marketplace-admin` — the schema slice **first**, then `yarn codegen`, then the routes and components.
  4. `docs/` — E17-S09's decision note and the `architecture.md` table.
  5. Parent workspace — one commit bumping every touched submodule pointer (ADR-031).
